# Performance, before and after

Measured on the deployed production site, `pharmaflow-bay.vercel.app`, with
Lighthouse 12, the default mobile throttling, and the same flags for both runs:

```bash
CHROME_PATH=/usr/bin/brave-origin npx -y lighthouse@12 <url> \
  --output=json --output-path=<file> --quiet \
  --chrome-flags="--headless=new --no-sandbox --disable-dev-shm-usage"
```

**Before** was measured on 2026-10-21 at 14:31, against the deployment that
carried the dark-first re-skin. **After** was measured on 2026-10-21 at 19:50,
against the deployment that carries this branch.

## What actually changed, and what it cost

### The sign-in page: 90 → 99

The largest single movement, and it is not a trick. The sign-in page's markup
is now smaller — one panel instead of a label and an input stacked — and the
fonts are subset and preloaded more carefully, and the two third-party
analytics scripts no longer load during hydration.

Speed Index 2.6s → 1.4s is the number that says it: the page is not just
faster at the end, it *looks* finished sooner.

### The landing page: 92 → 95, and accessibility 96 → 100

The accessibility score went to a hundred because of one change: the
`color-contrast` failure was the locale switcher's active button, which was
`text-white` on a light cyan. The switcher left the header, and the failure
went with it.

### The one thing that got worse, and what was done about it

The first "after" run measured the landing page at **92 → 92 with Total Blocking
Time 80ms → 120ms**. That was Vanta.js: three.js initialising on the main
thread.

Forty milliseconds is worth having on a laptop and is not worth having on a
phone. **And a field of points that responds to a pointer is a pointer
affordance** — on a touch screen it responds to nothing, and the main device
this product is used on is a phone in a van or a stockroom.

So the animated background now requires `(hover: hover) and (pointer: fine)`.
The phone gets the parchment, which is the design, and the three.js cost
leaves the mobile budget entirely — which is what the second run shows, with
TBT back at 80ms and LCP down to 2.9s.

**The cost, stated plainly:** the background is desktop-only now, and the
total payload on a desktop browser is roughly 120 KiB higher than it was
before this branch. That is the price of the animated home screen, it is
visible in the numbers rather than hidden, and it is paid on the one route
where the page has already painted.

## The changes behind the numbers

| Change | What it was worth |
|---|---|
| **GSAP removed** | ~70 KiB of gzipped JavaScript off the dashboard. The staggered reveal is a CSS animation with an `animation-delay` now, and the component stopped being a client component at all — the dashboard's reveal ships **zero** JavaScript. |
| **The analytics scripts deferred** | Two third-party scripts were loading during hydration, on every page, including the one whose LCP element somebody was waiting for. They now load on the window `load` event, after the page has painted. The data they collect is unchanged: the field data is about the load, not about the first byte. |
| **The Arabic fonts no longer preloaded** | Cairo and IBM Plex Sans Arabic are only used on the Arabic page, and a preload is a request the English page pays for and never uses. |
| **AVIF before WebP** | The modern codecs, for the product photography. |
| **A one-year cache on the hashed build output** | Vercel already served `/_next/static/**` immutably; the fonts and the icons were not covered, and both carry a content hash in their name. |
| **The label moved inside the field** | Fewer elements, and the sign-in page's markup is smaller for it. |
| **The dark theme became the base** | No theme-switch flash, and no `prefers-color-scheme` round trip. |

Two dependencies that were in `package.json` and used in **zero files** were
removed: `@tanstack/react-query` and `@hookform/resolvers`.

## The part that was not a performance change

Three of the tests I wrote in this branch were testing the *fixture* or the
*copy* rather than the code:

- the dashboard's charts, which are conditional on fulfilled deliveries that
  the CI fixture does not have;
- a heading matched against `/ranked|realised/` when the heading says "Top
  products by delivered margin";
- an empty state matched against `/nothing delivered/` when it says "Nothing
  has been delivered against a requisition".

All three are fixed, and the dashboard's panels now carry test ids so that a
copy change cannot break a smoke test. The chart's own mount is tested in
`charts.test.tsx`, where the data is deterministic.

The contrast harness was also measuring the wrong thing: it painted a
foreground onto a cleared canvas and threw away the alpha, so a 9% white
measured as pure white. That is how the dark theme's 1.28:1 hairline passed a
3:1 test, and how the dark inputs ended up fainter than the light ones
without anyone noticing. It now composites the foreground over its
background, because that is what a person actually sees.
